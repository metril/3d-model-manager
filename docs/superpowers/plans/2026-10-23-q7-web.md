# Q7-web plan: maintenance, smart plugs, backups, updates UI

Spec: `docs/superpowers/specs/2026-10-23-bambuddy-parity-v2-design.md` (Q7, Q3 footer slot). Backend: PR #24 (mocked in tests).

## API contract used (from q7-backend)
- `GET/POST /printers/{id}/maintenance`, `PATCH/DELETE .../{task}`, `POST .../{task}/done {note}`, `GET .../{task}/logs`, `PUT .../maintenance/mode {enabled}` (mutations: printers:control)
- `GET/PUT/DELETE /printers/{id}/plug` (PUT/DELETE: settings:write; GET 404 = none), `POST .../plug/on|off` (control)
- `GET/PUT /settings/ops` (settings:write; token write-only), `GET /admin/backups`, `POST /admin/backups/run`, `POST /admin/backups/{id}/restore-settings`, `GET /admin/support-bundle` (admin), `GET /system/update`

## Tasks
1. `api/types.ts` + `api/ops.ts` hooks (tasks, logs, mode, plug, ops settings, backups, update).
2. `components/maintenance/`: `MaintenanceSection` (tasks with due status, overdue highlight, Mark done + note, add/edit/delete, history, maintenance-mode switch with dispatcher note), `MaintenanceBadge` (due count; for Q3 BadgeRow).
3. `components/print/PlugRow.tsx` (state, W, toggle, auto-off; for Q3 CardFooter) rendered on `PrinterDetailPage` with the section and badge.
4. `components/settings/PlugConfig.tsx` in `PrinterSetupCard` per printer (kind tasmota|ha|mqtt|rest fields, auto-off, auto-on, remove); hidden without settings:write. HA entity is a plain entity-id input (no picker component exists; HaLinkDialog uses the same). Save validates server-side (no separate test endpoint exists).
5. `BackupsCard` (Storage tab), `UpdatesCard` (General tab, support bundle for admin), `shell/UpdateBadge` in `TopBar`.
6. Tests: vitest per component; `PrinterDetailPage.test` mock extended.
7. Gate: `npm run build`, oxlint `--max-warnings=13`, full vitest.
