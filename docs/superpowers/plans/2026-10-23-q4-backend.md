# Q4-backend: camera v2 (RTSP, external cameras, rotation, overlay tokens)


## Design
- `printers/camera_rtsp.py`: `JpegSplitter` (SOI/EOI scan, 8 MB bound), `FfmpegMjpegSource` (ffmpeg child -> MJPEG on stdout; exit before first frame raises so the worker backs off/restarts), Bambu URL/port consts + `BETA = True`.
- `printers/camera_external.py`: `ExternalCameraSource` for `mjpeg` (HTTP stream), `snapshot` (poll), `rtsp` (ffmpeg). Scheme-validated URLs.
- `printers/camera_select.py`: source choice (`external` > capability `a1|rtsp|none`), option normalise (encrypt URL with `app.crypto` Fernet -> `options.camera.url_enc`), redact for API output, decrypt in `connection_from_printer`.
- `BambuLanAdapter.open_camera` delegates to the selector (X1 `NotImplementedError` removed). Worker frame cap honours a per-source `min_interval`.
- API: `GET /printers/{id}/camera/status` (status, source, beta, rotation, default_fps); stream `?fps=1..15` (per-viewer throttle); snapshot rotated with Pillow per `options.camera_rotation` (stream rotation is client-side).
- Overlay tokens: table `overlay_tokens` (sha256 only), migration `b6d1e8a3c5f2` off `a8e2d4c6b1f3`. `POST/GET/DELETE /printers/{id}/overlay-tokens` (control). Public `GET /api/overlay/{printer_id}?token=`; stream/snapshot accept `ovl_` tokens scoped to their printer.
- Dockerfile already installs ffmpeg (timelapse) -- no change.
