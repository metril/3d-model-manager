# T6-web: 2FA + SMTP frontend

Coded against `2026-10-24-t6-be.md` (branch t6-be-2fa-smtp). No new npm dependency: QR is rendered client-side by `lib/qr.ts` (byte mode, ECC L, versions 1-10) + `components/ui/qr-code.tsx` (SVG).

## Contract used
- `POST /auth/login` -> 204 (logged in; `api.post` resolves `undefined`) | 200 `{requires_2fa:true, pre_auth_token, methods}`. Hook normalises to a `{requires_2fa:false}` / `{requires_2fa:true,...}` union.
- `POST /auth/2fa/verify`, `/auth/2fa/email/send` (public); OIDC redirect `/login?step=2fa&token=&methods=`.
- Self-service: `GET /auth/2fa/status`, `POST totp/setup|enable|disable`, `backup/regenerate`, `email/request|enable|confirm|disable`.
- Admin: `POST /admin/users/{id}/2fa/reset`, `GET/PUT /settings/security`, `POST /settings/server/smtp/test`, `config.smtp` in `/settings/server`, `trusts_idp_mfa` on OIDC providers.
- Coded errors are `detail: {code, message}`; `client.ts` now parses both that and legacy top-level `code`. 403 `2fa_enrollment_required` refreshes `me` (once) so the enrolment gate renders.

## Components
- `api/auth.ts` hooks; `api/security.ts`; `api/serverSettings.ts` smtp + `useSmtpTest`.
- `pages/LoginPage.tsx` (credentials -> 2fa state machine), `components/auth/TwoFactorStep.tsx`.
- `components/settings/TwoFactorCard.tsx` (+ `TotpSetupDialog`, `BackupCodes`), `pages/EnrollTwoFactorPage.tsx` (gate in `AppShell`).
- `SecurityCard` (require 2FA switch, Access tab), `OidcProvidersCard` trust switch, `UsersCard` Reset 2FA, `server/SmtpCard.tsx`.
