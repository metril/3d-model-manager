# P4 Live Camera and Timelapse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (or superpowers:executing-plans) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Live A1 camera on the dashboard and printer page, with one upstream connection per printer no matter how many tabs are open. Every finished run gets a snapshot and the printer's timelapse (as MP4 when ffmpeg is present). `timelapse` and `bed_levelling` finally reach the printer.

**Architecture:** A clean-room TLS client (`printers/camera_a1.py`) speaks the :6000 protocol and can be interrupted by an `Event` or by `close()`. printerd gets a `CameraSupervisor` with its own thread. It starts one `CameraWorker` per printer only while the Redis viewer ZSET is non-empty, publishes rate-capped frames to a Redis key plus a pub/sub channel, stops a worker 30 s after the last viewer leaves, and restarts stalled workers. The supervisor never runs on the status-poll or command threads. The API stays stateless: stream and snapshot routes register a viewer and read Redis, and authenticate by session cookie OR a scoped signed token (for `<img src>`). The archive task takes the snapshot by registering a short-lived viewer, so there is never a second socket to the printer. A follow-up io task picks the newest timelapse and a cpu task transcodes it with ffmpeg.

**Tech Stack:** Python 3.12 stdlib `ssl`/`socket`/`threading`, redis-py (sync in printerd/Celery, asyncio in API), FastAPI `StreamingResponse`/`FileResponse` (Starlette 1.3.1, Range-capable), Celery io/cpu queues, ffmpeg (apt), React 19 + TanStack Query + Vitest.

**Spec:** `docs/superpowers/specs/2026-10-21-bambuddy-parity-design.md` §P4 (+ §Integration rule: camera view = `printers:control` per printer).

**Branch:** `p4-camera` from `main`. Leave `compose.yaml` (uncommitted local change) alone. Agents never `git stash`/`checkout`. Cap pytest with `timeout 600`.

## Global Constraints

- Commit: `git -c user.name=metril -c user.email=1517921+metril@users.noreply.github.com commit -m "<type(scope): subject>"`. No trailers, no AI mention.
- Backend gates: `cd backend && timeout 600 uv run pytest tests/<file> -q`, `uv run ruff check . && uv run ruff format --check .`. Web: `cd web && npx vitest run <file>`, `npm run build` (`tsc --noEmit` is a no-op here), `npx oxlint` (no new warnings vs baseline).
- Protocol: TLS (no verify, `check_hostname=False`) to `host:6000`. Auth packet = 80 bytes: `<IIII` `(0x40, 0x3000, 0, 0)`, then `bblp` and the access code, each ASCII NUL-padded to 32. Frame = 16-byte header (first `<I` = payload length) + JPEG `ff d8 … ff d9`. `MAX_FRAME_BYTES = 4 * 1024 * 1024`, `CONNECT_TIMEOUT_S = 5.0`, `SOCKET_TIMEOUT_S = 5.0` (no bytes within this time raises `CameraTimeout`), recv chunk 4096, `close()` must unblock `recv` in under 1 s.
- Redis (`app/services/camera_state.py`, the single source of these names):
  - `viewers_key(id) = "printer:{id}:camera:viewers"` is a **ZSET**. Member = viewer uuid, score = expiry epoch seconds (`now + VIEWER_TTL_S`). Prune with `ZREMRANGEBYSCORE -inf now`, and the key gets `EXPIRE 60`.
  - `frame_key(id) = "printer:{id}:camera:frame"` holds bytes, `EX FRAME_TTL_S`.
  - `frame_channel(id) = "printer:{id}:camera:frames"` (pub/sub, raw JPEG bytes).
  - `status_key(id) = "printer:{id}:camera:status"` holds `connecting|live|error|unsupported`, `EX 15`.
  - `job_frame_key(id, job_id) = "printer:{id}:camera:job:{job_id}"`, `EX 3600`.
- Timings: `VIEWER_TTL_S = 10`, `HEARTBEAT_S = 5`, `FRAME_TTL_S = 5`, `MIN_FRAME_INTERVAL_S = 0.2` (~5 fps cap), `IDLE_STOP_S = 30`, `STALL_S = 15` (watchdog restart), `JOIN_TIMEOUT_S = 2.0`, supervisor tick `1.0` s, reconnect backoff `2 → 60` s doubling, API `STREAM_IDLE_S = 20` (the stream ends after 20 s with no frame), snapshot 503 sends `Retry-After: 2`, archive snapshot wait `12` s.
- Camera auth: the routes live on `printers.camera_public_router` (mounted on `api_router` like `files.public_router`). Each route first checks `?token=` or the session cookie (no credentials → 401), then the `printer_enabled` flag, then `ctx.require_printer(id, "control")` (403). A token comes from `signed_urls.sign_scoped(settings, f"camera:{printer_id}:{user_id}", ttl_s=600)`. Verification re-loads the user (`is_active`) + `load_grants` and re-checks control, so a revoked ACL kills new connections.
- Archive media: `BlobKind.VIDEO="video"`, `BlobFormat.MP4="mp4"`, `BlobFormat.AVI="avi"`. Snapshot is stored as `archive_path(sha,"jpg")` (`BlobKind.IMAGE`/`JPG`). New `print_archives.media_note text NULL` holds non-failure notes; `fetch_state` is never touched by media. Note strings: `"no timelapse found"`, `"ffmpeg unavailable; original .avi kept"`, `"transcode failed: <type>"`, `"no camera frame"`.
- Timelapse: dirs `("/timelapse", "/timelapse/video")` (both listed, errors per dir ignored), extensions `.mp4`/`.avi`. Pick the newest file with `mtime >= started_at - TIMELAPSE_SLACK_S (120)`. FTPS `LIST` times are treated as UTC (live-verify). `fetch_timelapse` runs on io with `countdown=90`, `max_retries=3`, `countdown=120` between retries. `transcode_timelapse` runs on cpu (route `"app.tasks.media.*": {"queue": "cpu"}` placed BEFORE the `app.tasks.*` catch-all). ffmpeg command: `ffmpeg -nostdin -y -loglevel error -i in.avi -c:v libx264 -preset veryfast -pix_fmt yuv420p -movflags +faststart out.mp4`, `timeout=600`.
- Web: camera URL query key `["camera-url", printerId]`, deliberately NOT under `["printers"]`, so SSE invalidation never mints a new token and reconnects the `<img>`. `staleTime 5 min`, `refetchOnWindowFocus false`. The CameraTile is rendered only when `can_control`.
- The API/worker never import `camera_a1` (flag-off import safety and a single upstream connection). Only printerd does, through `adapter.open_camera`.
- Visual tasks (8, 9) invoke the `frontend-design` skill first.

```python
HEADER_LEN = 16; JPEG_SOI = b"\xff\xd8"; JPEG_EOI = b"\xff\xd9"
class CameraError(OSError): ...
class CameraTimeout(CameraError): ...
class CameraAuthError(CameraError): ...      # peer closed (b"") before any frame
class CameraProtocolError(CameraError): ...

def auth_packet(username: str, access_code: str) -> bytes:
    u, c = username.encode("ascii"), access_code.encode("ascii")
    if len(u) > 32 or len(c) > 32:
        raise ValueError("username/access code longer than 32 bytes")
    return struct.pack("<IIII", 0x40, 0x3000, 0, 0) + u.ljust(32, b"\0") + c.ljust(32, b"\0")

class FrameParser:
    def __init__(self) -> None:
        self._buf = bytearray()
    def feed(self, data: bytes) -> list[bytes]:
        self._buf += data
        out: list[bytes] = []
        while len(self._buf) >= HEADER_LEN:
            (size,) = struct.unpack_from("<I", self._buf, 0)
            if size == 0 or size > MAX_FRAME_BYTES:
                self._buf.clear()
                raise CameraProtocolError(f"bad frame length {size}")
            end = HEADER_LEN + size
            if len(self._buf) < end:
                break
            payload = bytes(self._buf[HEADER_LEN:end])
            del self._buf[:end]
            if payload[:2] == JPEG_SOI and payload[-2:] == JPEG_EOI:
                out.append(payload)          # non-JPEG payloads are dropped, not fatal
        return out

class CameraA1Client:  # context manager; __enter__ connects + sends auth_packet
    def __init__(self, host: str, access_code: str, *, port: int = 6000, username: str = "bblp",
                 connect_timeout: float = CONNECT_TIMEOUT_S, read_timeout: float = SOCKET_TIMEOUT_S,
                 stop: threading.Event | None = None) -> None: ...
    def frames(self) -> Iterator[bytes]: ...  # returns when stop is set; raises CameraTimeout/CameraAuthError
    def close(self) -> None: ...              # idempotent, thread-safe, safe before __enter__; shutdown(SHUT_RDWR)+close
```
`frames()` loops `recv(4096)` with a socket timeout of `min(read_timeout, 0.5)`. It checks `stop` each iteration and raises `CameraTimeout` once `read_timeout` passes with no bytes. Exception messages never include the access code.
